# 切页、解析与容错策略

这份文档把“怎么切页、怎么建树、遇到不规整输入怎么补救、增量为什么
一定对”四件事讲清楚。所有容错位置都会在解析结果的 `recoveries`
里逐条标注（类型、页内行号、补救方式 `detail.resolution`、给写作者
的中文说明），让每一处被“猜”出来的地方都可见。

## 1. 词法切分（`parser/lexer.py`）

先做输入规范化：去除开头 UTF-8 BOM（标 `bom_stripped`），CRLF/CR
统一成 LF。然后**线性扫描**，维护代码围栏状态，产生 token：

- `page_break`：独占一行、由 3 个或更多 `-` 组成（允许首尾空白）；
- `fence_begin` / `fence_end` / `fence_line`：围栏的开、关、内部行；
- `plain`：其它普通行。

**硬规则：围栏代码块里的 `---`、`#`、列表记号一律是普通文字。**
第一遍严格扫描时，只有语法正确的关围栏（同字符、长度不短于开围栏、
缩进不超过开围栏、info 为空）能合上围栏，内部任何 `---` 都只是
`fence_line`。因此一个**正常闭合**的代码块里出现再多分隔线也不会
翻页——这条不靠猜。

## 2. 翻页切分（`parser/splitter.py`）

切页器只按 `page_break` token 做线性分组，不判断围栏（围栏状态已经
在词法层解决）。每页首尾的空白行会被裁掉、页内空行保留：这样
“一页全是空白”和“空页”不会仅仅因为多一个空格行就结构不同，
**页结构只取决于实际内容**，这是页可缓存复用的前提。

空文本 → 零页（不报错）；只有空白字符 → 一页零块。连续分隔符、
首尾分隔符产生的空页保留（“一页空白”也是一页）。

## 3. 块级与行内解析

- 块级（`parser/blocks.py`）：标题（ATX，1–6 级，`#` 后必须有空白，
  否则是普通段落）、段落、围栏代码块、引用（`>`，可嵌套）、
  有序/无序列表。列表先线性拍平成带 **marker 绝对列** 的 item 记录
  （tab 按 4 列制表位折算），再用“源序最近的、列严格更小的项即父项”
  建树。层级照实保留，二级项不会被压成一级；空格/tab 混用、不同缩进
  档位都不丢层级。列表项与引用内部递归复用同一个块解析器。
- 行内（`parser/inline.py`）：文本与定界符分两轨。第一趟产出文本片
  （转义、行内代码、链接、图片）和强调定界符 run；第二趟在定界符上
  跑 CommonMark 的 flanking + 奇偶配对，记录精确字符区间后建树。
  配对规则写死、无随机/无外部状态，**同一段文本解析任意遍逐字段相同**。

产出是 `Document → Page → Block → Inline` 的结构树（`parser/model.py`），
节点带类型与页内位置，而不是拼好的 HTML。

## 4. 容错策略

原则：**残缺输入不能让整篇崩掉，也不能吞掉后文；每处补救都标注。**

### 4.1 未闭合代码围栏（`unclosed_fence`）

两种说得过去的做法及代价：

- A. 一路吞到文末。优点是严格符合“围栏已打开”的事实；缺点是只要漏
  一个 ` ``` `，后面**所有幻灯片**都变成代码，代价过大。
- B. 在下一个翻页符处截断。优点是把破坏限制在当前幻灯片，后续页
  照常解析；缺点是若作者本来就想让 `---` 属于代码，会被提前合上。

**本项目选 B，并在词法层用两遍扫描实现**：第一遍严格扫描定位仍开着
的围栏；若存在，在其开行行号之后找最早的独占 `---` 行作为“强制
翻页点”，带着该信息重扫（可迭代收敛，处理多个未闭合围栏）。于是：

- 正常闭合围栏内的 `---` 永远不翻页（第一遍就排除了）；
- 忘了关的围栏只吞到下一个翻页符，后续页不受影响；
- 文末仍未闭合时才一路吞到文末。

块级解析器在页内独立扫描围栏、并知道“页首一定是围栏关闭态、页内
不会出现翻页行”，所以它与词法层结论严格一致。未闭合块带
`closed=false`，`recoveries[].detail.resolution` 为：

- `cut_at_page_break`：非最后一页，在翻页符处隐式合上；
- `swallowed_to_eof`：最后一页，一路吞到文末。

### 4.2 井号后为空（`empty_heading`）

`#`、`## ` 等保留为对应级别的空标题（不丢行、不吞后文），标 `info`
级容错。理由：作者多半是先打标题占位，吞成普通文本反而更难发现。

### 4.3 列表缩进混用空格与制表符

- tab 一律按 4 列制表位折算，标 `tab_indent_normalized`（info）；
- 同一列表内缩进风格在空格/tab 间切换时，再加一条
  `mixed_indentation`（warning），层级仍按折算后的列如实保留。
  标注 `detail.prefix_repr` 与 `column`，方便作者定位、统一写法。

### 4.4 未闭合行内代码（`unclosed_code_span`）

找不到等长反引号串配对时，开记号按普通文字原样保留，后续内容继续
正常解析（不吞后文），标 warning，带 `opener_col` 与反引号数量。

### 4.5 未配对强调定界符

不成对的 `*`/`_` 按普通字符输出——这是 flanking 规则的正常结论，
不算“猜”，因此不打容错标注。

## 5. 增量重算为什么一定与全量一致

`ParseEngine.apply_incremental`（`parser/engine.py`）：

1. 页结果只依赖 **该页 token 切片** 与 **是否最后一页**（后者只影响
   未闭合围栏收尾文案，不影响块结构）。位置全部用页内相对行号。
2. 编辑应用到文本后，用**与解析器同源**的 `tokenize + split_pages`
   得到新旧页源（不能朴素按 `---` 切，因为有 4.1 的强制翻页策略）。
3. 对新旧页源做最长公共前缀/后缀：公共页因为“页源相同 ⇒ 解析结果
   相同”直接复用旧 `Page` 节点；中间页从整篇新文本的 token 切片
   重新 `build_page`（中间页必须来自整篇切片——单独 tokenize 一个
   页源字符串会让未闭合围栏的截断判定脱离全局而不一致）。
4. 最后一页身份变化（新增/删除翻页符导致尾部页变非末页）时，只重打
   围栏收尾标注，结构不重算；页号统一重排。

因此任意一串编辑后，增量结果 = 对最终文本一次全量解析，页号、块结构、
容错标注逐字段一致。测试 `tests/test_incremental.py` 用随机编辑序列
对拍（开发期另跑了 2 万组更重的随机用例）。响应里的
`recomputed_pages` / `reused_pages` 明确告知这次实际重算了哪几页。

## 6. 存储与解析的咬合

- 修订不可变：每次保存新增一行 revision（1,2,3,…），历史不改不删；
- 乐观锁：保存必须带 `base_revision`，过期返回 409 与当前修订/内容，
  前端弹冲突框让人选保留哪份或手动合并，绝不静默覆盖；
- 解析缓存以 `(document_id, revision)` 为键，**每个修订一个独立
  ParseEngine**，增量缓存绝不跨修订串用；
- 结构树不入库，按修订取回时现解析。不变量：按修订号取回的树
  ≡ 对该版文本全量解析（有专门测试）。
